## Controls built into PX2b (all Rust, no Bun)
1. **Door token** (`signx.token`) -> required for every public question; stateless HMAC, 10 min, purpose bound, key bound, constant-time compare. Tested for expiry / tamper / wrong purpose / future time.
2. **Rate window** per client address (Caddy appends the real peer as the LAST X-Forwarded-For entry; client-supplied earlier entries are ignored). 429 with the same body shape.
3. **Country wall** (GEO1): AF / IL / KP refused for country, phone prefix and best-effort timezone; the edge IP block is Caddy (`remote_ip` matcher from RIR address lists; no plugin, no account).
4. **Phones:** E.164 only, max 5 (DB trigger + code), duplicates on one account refused, same number on other accounts allowed (founder), blind-index HMAC stored, plain number visible only to its owner, never logged.
5. **Passkey:** UV required, discoverable credentials for new passkeys, username-less login (PX2b-2), owner notified on add / recovery. Founder + family exempt as ordered.
6. **Audit:** every refused / blocked attempt writes country code + time only (no personal data). SHA-256 chain for sign-up events comes with the founder audit feed (later).
7. **Headers (Caddy):** HSTS, CSP, no sniff, frame deny, Referrer-Policy — to be CHECKED read-only first (not changed without his haan).

## What we do NOT claim
No FIPS 140-3 validation, no CNSA 2.0 compliance, no AAL3 for synced passkeys, no protection against a user typing the same password elsewhere. VPN cannot be blocked 100% (see GEO1).

Sources: NIST SP 800-63B-4 syncable authenticators page; OWASP ASVS 5.0 V6.3.8 (via safeguard.sh summary); NSA CNSA 2.0 overview (Entrust).
