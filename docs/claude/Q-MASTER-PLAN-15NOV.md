## 3. THE SQL STANDARD ("above super advanced", what every Q SQL file must meet; the founder code-quality law of 3 Nov)
Each file = blank first line (Rule 42.1), `sql-editor-lint.py` clean, own `CHECK_E<n>.sql` that fails when the thing is broken (tamper-tested like CHECK_E172), a rolling-back `selftest` function, run only by `sql-run.sh` in number order, never re-sent once green.
1. **Zero trust in the database role**: every door is `security definer` with a fixed `search_path`, `revoke ... from public, anon, authenticated`, `grant ... to service_role` only, and the CHECK asserts that no door is executable by anon/authenticated.
2. **RLS forced** on every table (`alter table ... force row level security`), policies deny by default; the founder tables are reachable only through doors.
3. **Append-only hash-chained ledgers**: one writer (advisory lock) so no fork, `fmail-ledger-v1` length-prefixed SHA-256 (no ambiguity attacks), UPDATE/DELETE/TRUNCATE blocked by trigger, genesis zeros, chain verified by CHECK and now by the browser kernel; periodic anchor into `founder_audit` (Merkle, signed checkpoints, OpenTimestamps/RFC 3161 already live).
4. **Closed lists and state machines**: CHECK constraints for every enum, transition triggers (a message cannot jump from `quarantined` to `delivered`), `not null` + domain types, no free text where a list will do.
5. **Sealed data**: the database never sees plaintext bodies or keys; bodies AES-256-GCM sealed in Rust, blind indexes (HMAC) for search keys, per-message key wrapped by ML-KEM-768 + X25519; pgcrypto only for digests.
6. **Performance by design**: keyset pagination (never OFFSET), partial and covering indexes, `tsvector` + GIN for search on blind/derived fields only, time-partitioned latency samples (QPERF), `percentile_cont` for p50..p99.9 (+ an exact-rank method, no sampling lies), statement and lock timeouts on every door.
7. **Correctness tools**: `tstzrange` + exclusion constraints (`btree_gist`) so calendar events cannot overlap where the rule forbids it (Q1e), deferrable foreign keys, generated columns for derived values, idempotent files (`if not exists`, `create or replace`), `immutable`/`stable` marked correctly (E172 is `stable`, read-only).
8. **Honest proof, always**: the CHECK prints the numbers (rows returned, bad hashes, broken links), the selftest rolls itself back, and I prove tamper detection in a sandbox PG16 before it goes to his server. No SQL is called green before his paste.
