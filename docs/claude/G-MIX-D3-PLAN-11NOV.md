## What the screen is (the advanced part, every pixel backed by a real field)
1. **Trust Ring (hero).** One SVG ring of 4 arcs for THIS session, each arc a real fact: Device key (key_source dbsc/webcrypto/none + fingerprint), Path (HTTP/3 QUIC vs TCP, measured by the server), Integrity (verified / stale / failed / never, last verified time), Chain (ledger tail verifies + anchor matches). Centre = one honest word: "All clear" / "Needs attention" / "Alert" derived by a PURE function (tested), never by colour alone: each arc also has an icon and a text label.
2. **Live sessions** as rows that become stacked cards under 560 px container width: this-device marker, method (passkey/password), browser claimed vs proven (mismatch shown as a clear "claims Chrome, proves Safari" line), spoof meter 0-100 with the SQL reasons translated to plain words, key chip, path badge, country flag + name, kernel build, network flips / failure streak, first seen, last seen (relative + exact on focus/hover), idle/absolute remaining from the policy.
3. **Safe nuke.** "Close this session" = click then an inline "Confirm close" (no drag, no hold, keyboard friendly, WCAG 2.5.7). Closing the CURRENT session says so first and signs this browser out after the server confirms. "Sign out everywhere else" = same two-step, shows how many were closed. Buttons disable while pending; the list reloads from the server after every action (no optimistic lie).
4. **Alert strip.** The last 24 h of ledger kinds that matter (spoof_alert, spoof_blocked, identity_drift, geo_moved, geo_refused, net_flapping, session_cap, integrity_fail) as dismissible-for-this-view chips with counts; each opens the ledger filtered to that kind.
5. **Ledger timeline.** Newest first, paged by `before` id (50 per page, "Load older"), kind icon + plain sentence ("A stolen-looking token was refused: used outside the allowed country"), expandable facts (rendered as text only), a "Chain verified" badge and an "Anchor matches the audit chain" badge straight from the board (`ledger_chain.ok`, `anchor.ok`); if either is false the page says it in red text AND an icon, with the broken row id.
6. **Location lock card.** Read-only today: geo mode (off / observe / enforce), allowed countries, idle and absolute lifetimes, session cap, flap limit; the honest line "Changing these needs a fresh passkey touch (D2b-5)" and the honest limit "a VPN inside an allowed country passes the lock".
7. **Filters + search** (client side, over the 60 rows the board returns): All / Live / Closed / With alert; type to find by browser, country, kernel, short sid.
8. **Honest states.** Loading skeleton; "Devices & Sessions SQL is not answering" when `available:false`; "No other sessions" empty state; error banner with retry that keeps the last good data and shows "Updated hh:mm:ss, stale" instead of blanking.
## Loopholes found in the plan before coding (U1-U9) and their fix
U1 secrets: only the 12-char sid and 16-char key fingerprint the SQL already trims are ever shown; never the sid_hash in text (it is only sent in the revoke POST). U2 revoking the current session must not leave a zombie screen: after ok -> signOut(). U3 double click / race: per-row pending lock, one in-flight action at a time. U4 stale data lie: every refresh stamps "Updated", a failed refresh keeps data but flags it stale. U5 colour-only meaning: every state = icon + word + colour. U6 untrusted text: unknown kind / reason / protocol values render through a fallback ("Unknown event: kind") and always as text, never HTML. U7 huge ledger: paged, never more than 200 rows per call, DOM capped at 400 rows. U8 time: server ISO strings and ms epochs parsed defensively, invalid = "unknown". U9 mobile: 44 px targets, wrapped long values, no sideways scroll, controls reachable with thumb, tested at 390 / 820 / 1280.
