## Loopholes found (fixed in the new awam passkey; the old file is not edited until AP3 replaces it)
1. **Account oracle:** /passkey/options takes an email and answers "No passkey on this account. Use your password." -> anyone can learn which emails have passkeys, and gets the credential ids. Fix: discoverable credential, NO email, same generic answer always.
2. **Distinct errors** (passkey_unknown vs passkey_challenge_expired vs passkey_user_missing) = more oracle. Fix: one generic 401.
3. **No network limit / lock** on passkey failures and no hash-chained sign-in ledger for awam. Fix: awam copy of E151/E153 pattern (own tables, own numbers).
4. **Challenge rows in a table without a per-network cap** (spam). Fix: in-memory fair ceremony store (as founder) or capped SQL door.
5. **Direct table reads/writes by service key** for credentials. Fix: SQL doors + posture proof (E154 pattern).
6. **sign_count / clone detection** only inside verify: make it a SQL door that revokes a cloned key and writes the ledger (E117 founder pattern).
7. **Bun/Node runtime** is banned for the website server by his law; the awam migration to Rust (K5b) is the home for the new door. Until then the awam door is written as Rust first and the Bun route is kept only as the live fallback.
